# Prompt: convert raw LLM usage data into the app's Import JSON format

Copy-paste the version you need (ES / EN) to any LLM, attach your raw data
(OpenRouter export, CSV, console screenshot transcript, vendor dashboard numbers…),
and paste the resulting JSON into the app's **Import JSON** window
(paste box or `.json` file — both work).

---

## ES — convierte mis datos de consumo al formato de importación

Vas a convertir mis datos de consumo de LLMs al formato JSON que acepta mi
calculadora de costes. Devuelve SOLO el JSON, sin explicaciones ni fences extras
(un único bloque ```json está bien).

### Formato 1 — registros diarios (preferido si mis datos vienen por día)
Un ARRAY, un objeto por día:
```json
[
  { "time": "2026-09-03", "hit": 55153280, "miss": 1078210, "output": 520153 }
]
```
- `time`: fecha del día (cualquier formato de fecha legible vale).
- `hit`: tokens de ENTRADA servidos desde caché (prompt caching / cache hit).
  Si mis datos no distinguen caché, pon `hit: 0` y suma todo en `miss`.
- `miss`: tokens de ENTRADA procesados de cero (cache miss / input normal).
- `output`: tokens GENERADOS por el modelo (completion / output).
- Todo en NÚMEROS enteros de tokens (no "1.2M", no strings): convierte
  1K=1000, 1M=1000000.

### Formato 2 — total directo (si solo tengo totales acumulados)
Un OBJETO con los totales y a cuántos días corresponden:
```json
{ "hit": 900000000, "miss": 30000000, "output": 15000000, "days": 30 }
```

### Reglas
1. No inventes cifras. Si un dato no existe, usa 0 y avísame en UNA línea fuera del JSON.
2. Si mis datos mezclan varios modelos o días, agrega por día (suma).
3. Ignora costes en $/€: aquí solo van TOKENS.

### Mis datos (pego debajo de esta línea)
[PEGA tus datos aquí]

## EN — convert my usage data to the import format

Convert my LLM usage data into my cost calculator's JSON import format.
Return ONLY the JSON, no explanations (a single ```json block is fine).

### Format 1 — daily logs (preferred if my data is per-day)
An ARRAY, one object per day:
```json
[
  { "time": "2026-09-03", "hit": 55153280, "miss": 1078210, "output": 520153 }
]
```
- `time`: the day's date (any readable date format is fine).
- `hit`: INPUT tokens served from cache (prompt caching / cache hit).
  If my data doesn't split cache out, set `hit: 0` and put everything in `miss`.
- `miss`: INPUT tokens processed from scratch (cache miss / plain input).
- `output`: tokens GENERATED by the model (completion / output).
- All as INTEGER token counts (not "1.2M", not strings): 1K=1000, 1M=1000000.

### Format 2 — direct total (if I only have accumulated totals)
One OBJECT with totals plus how many days they cover:
```json
{ "hit": 900000000, "miss": 30000000, "output": 15000000, "days": 30 }
```

### Rules
1. Don't invent numbers. If a value is missing, use 0 and tell me in ONE line outside the JSON.
2. If my data mixes models or days, aggregate per day (sum).
3. Ignore $/€ costs: TOKENS only here.
